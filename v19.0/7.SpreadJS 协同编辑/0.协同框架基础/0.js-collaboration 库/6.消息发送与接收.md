# messages-sending-and-receiving

`js-collaboration` 支持客户端与服务器双向通信，并允许服务器向房间内所有客户端发起消息广播。本文档详细介绍以下技术实现：

* 客户端向服务器发送消息
* 服务器接收并响应消息
* 消息广播

## 基础收发流程

### 客户端 → 服务器

客户端使用 [connection.send()](gcdocsite__documentlink?toc-item-id=01f01f56-2c37-4f99-b868-ac32e2c7e57b#send) 方法向服务器发送消息，支持字符串、普通对象、数字、数组等多种数据类型。

```typescript
// 客户端
// 向服务器发送消息
connection.send('hello, world!');
```

服务器可通过 `message` 钩子接收客户端消息：

```typescript
// 服务器
server.on('message', ({ connection, data }) => {
    console.log('收到客户端消息:', data);
});
```

### 服务器 → 客户端

客户端通过 [connection.on('message')](gcdocsite__documentlink?toc-item-id=01f01f56-2c37-4f99-b868-ac32e2c7e57b#on) 接收服务器消息：

```typescript
// 客户端
connection.on('message', (data) => {
    console.log('收到服务器消息:', data);
});
```

服务器使用 [connection.send()](gcdocsite__documentlink?toc-item-id=464e75e4-bb2c-4163-8997-3a576676fe36#send) 向客户端发送消息：

```typescript
// 服务器
server.on('connect', ({ connection }) => {
    connection.send('hello, world!');
});
```

## 服务器广播

服务器不仅可向单个客户端发送消息，还能通过 [connection.broadcast()](gcdocsite__documentlink?toc-item-id=464e75e4-bb2c-4163-8997-3a576676fe36#broadcast) 向房间内所有其他客户端广播消息。

### 排除发送者的广播

当 `connection.broadcast()` 仅提供 `roomId` 参数时，默认行为是排除发送者的广播。
![messages_sending_and_receiving-broadcast1](/DOCUMENT_SITE_LINK_PREFIX_HERE/document-site-files/images/1f04de1b-0add-4f88-889e-295f2a2e218b/messages_sending_and_receiving-broadcast1.1a1948.9d89b9.png?width=800)

```typescript
// 客户端
connection.on('message', (data) => {
    console.log('收到服务器消息:', data);
});
```

```typescript
// 服务器
server.on('connect', ({ connection, roomId }) => {
    // 客户端连接时，向房间内所有客户端广播消息（排除发送者）
    connection.broadcast(`${connection.id} 加入 ${roomId}`);
});
```

### 包含发送者的广播

若需向房间内包括发送者在内的所有参与者广播消息，需配置 `includeSelf: true`：
![messages_sending_and_receiving-broadcast2](/DOCUMENT_SITE_LINK_PREFIX_HERE/document-site-files/images/1f04de1b-0add-4f88-889e-295f2a2e218b/messages_sending_and_receiving-broadcast2.a16051.862bde.png?width=800)

```typescript
// 客户端
connection.on('message', (data) => {
    console.log('收到服务器消息:', data);
});
```

```typescript
// 服务器
server.on('connect', ({ connection, roomId }) => {
    // 客户端连接时，向房间内所有客户端广播消息（包含发送者）
    connection.broadcast(`${connection.id} 加入 ${roomId}`, '', true);
});
```

>type=note
> `broadcast()` 的第二个参数为消息类型（可选），此处为空字符串。

## 消息类型

消息类型用于标识消息的用途或类别，以便接收方判断消息是否与自身相关。例如在协同场景中，可使用 `"my-document"` 或 `"my-presence"` 区分文档更新消息和用户状态消息：

```typescript
// 发送文档更新
connection.send({ content: '新段落' }, 'my-document');
// 发送在线状态
connection.send({ userId: 'user1', active: true }, 'my-presence');
// 接收并区分消息
connection.on('message', (data, type) => {
    if (type === 'my-document') {
        console.log('文档更新:', data);
    } else if (type === 'my-presence') {
        console.log('状态更新:', data);
    }
});
```

## 消息顺序

`js-collaboration` 保证消息按发送顺序投递。例如：

```typescript
connection.send('msg1');
connection.send('msg2');
connection.send('msg3');
```

接收方始终按 `msg1`、`msg2`、`msg3` 的顺序接收消息。

## 消息投递机制

### 投递保证

`js-collaboration` 实现 **至多一次投递（At-Most-Once Delivery）** 机制，定义如下：

* 若消息在连接断开时发送，系统无法保证接收方已收到消息。
* 断开后重连时，不会自动重发未投递的消息。

### 客户端行为

连接断开时，客户端采用缓冲策略尝试保留未发送的消息：

* **缓冲未发送消息**：当客户端调用 `connection.send()` 且连接不可用（如网络中断）时，消息不会立即丢弃，而是在客户端本地缓冲。
* **重连后发送**：连接恢复后，缓冲的消息按原顺序发送。

### 服务器行为

服务器不提供消息缓冲机制，客户端断开时发送的消息直接丢失：

* **不缓冲消息**：服务器使用 `connection.send()` 或 `connection.broadcast()` 发送消息时，若目标客户端断开，消息不存储。
* **不重发**：客户端重连后，服务器不补发自断开期间丢失的消息。

## 处理消息丢失的策略

由于 **至多一次投递** 机制，需根据业务需求设计额外的可靠性机制。以下是常见策略：

#### 应用层确认机制

* **方法**：发送方在消息中包含唯一标识符（如消息ID），接收方返回确认消息。
* **实现**：若未收到确认，发送方可重试。
* **场景**：关键消息（如文档变更）。

```typescript
// 客户端发送带ID的消息
connection.send({ id: 'msg123', type: 'update', content: 'xxx' });

// 服务器确认
server.on('message', ({ connection, data }) => {
    connection.send({ id: data.id, type: 'ack' });
});

// 客户端检查确认
connection.on('message', (data) => {
    if (data.type === 'ack' && data.id === 'msg123') {
        console.log('消息已投递');
    }
});
```
