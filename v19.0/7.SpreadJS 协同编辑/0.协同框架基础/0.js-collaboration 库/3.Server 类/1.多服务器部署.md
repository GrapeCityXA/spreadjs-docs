# multiple-servers-deployment

在生产环境中，若**SpreadJS 协作服务器**需处理高并发或实现高可用，通常会在负载均衡器后端部署**多个服务器实例**。

然而，当用户连接至不同服务器时，可能会出现**消息广播问题**。例如，连接到“A服务器”的用户，无法与同一协作房间内连接到“B服务器”的用户进行通信或共享实时更新内容。

为解决该问题，SpreadJS 协作功能支持集成**[Socket.IO 适配器](https://socket.io/docs/v4/adapter/)**。该适配器可确保所有协作事件与消息在各服务器实例间无缝分发，使所有连接的客户端无论接入哪个节点，都能实现实时同步。

## 前提条件
| 组件 | 说明 |
| ---- | ---- |
| Node.js | 16 及以上版本 |
| Redis 服务器 | 7.0 及以上版本，且所有协作服务器均可访问 |
| @grapecity-software/js-collaboration | SpreadJS 协作服务器程序包 |
| @socket.io/redis-adapter | 用于多节点通信的 Redis 适配器 |
| 负载均衡器 | Nginx、Kubernetes Service 或同类产品 |

## 功能说明
### 可扩展协作架构
* 支持通过 Socket.IO Redis 适配器实现**多服务器部署**。
* 在服务器间同步**实时协作数据**（工作簿更新、选区状态、连接事件）。
* 确保所有用户会话间的**数据一致性与同步性**。
* 兼容**负载均衡**系统（Nginx、Kubernetes 等）。

### Redis 发布/订阅机制
该适配器依托 Redis**发布/订阅（Pub/Sub）** 机制实现以下功能：
* 将单个服务器的套接字事件广播至其他所有服务器。
* 向所有服务器通知同一协作房间内的更新信息。
* 维持连接至不同实例的用户之间的数据同步。

## 使用说明
### 安装依赖
在服务器项目目录中执行以下命令，并确保 Redis 服务器已启动且所有节点均可访问：
```auto
npm install @grapecity-software/js-collaboration
npm install redis
npm install @socket.io/redis-adapter
```

### 集成 Socket.IO Redis 适配器
在协作服务器配置文件（如 `server.js`）中插入以下代码：
```auto
import { Server } from '@grapecity-software/js-collaboration';
import { createClient } from 'redis';
import { createAdapter } from '@socket.io/redis-adapter';
// 1. 初始化发布/订阅客户端
const pubClient = createClient({ url: 'redis://localhost:6379' });
const subClient = pubClient.duplicate();
await Promise.all([pubClient.connect(), subClient.connect()]);
// 2. 注入适配器
const server = new Server({
    port: 8080,
    socketIoAdapter: createAdapter(pubClient, subClient)
});
```

### 负载均衡器配置
需通过**负载均衡器**将用户流量分发至多个服务器实例，以下为两种推荐部署方案。

#### Nginx 部署示例
以 Nginx 作为反向代理，可通过 **upstream** 块定义服务器列表，并配置 **WebSocket** 协议升级（Upgrade）请求头。
* **Upstream**：定义后端服务器节点的 IP 地址与端口。
* **Upgrade 请求头**：必须显式设置 `Upgrade` 与 `Connection` 请求头，以支持 WebSocket 握手。
```auto
http {
  # Define backend server list
  upstream nodes {
    server 103.32.2.101:3000;
    server 103.32.2.102:3000;

    server 103.32.2.103:3000;
  }

  server {
    listen 3000;
    server_name yourhost.com;

    location /collaboration {
      proxy_pass http://nodes;

      # Enable WebSocket support
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
      
      # Pass real IP (optional)
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header Host $host;
    }
  }
}
```

#### Kubernetes（K8s）部署示例
Kubernetes 可通过**副本集**与**服务暴露**实现可扩展、自修复的部署方案。
* **replicas**：多实例部署时设置为 3 个及以上副本。
* **环境变量**：通过 `env` 变量传入 Redis 与数据库地址，确保所有 Pod 连接至同一 Redis 服务。
```auto
apiVersion: apps/v1
kind: Deployment
metadata:
  name: collaboration-app
spec:
  replicas: 3 # Number of replicas for multi-server setup
  selector:
    matchLabels:
      app: collaboration-app
  template:
    metadata:
      labels:
        app: collaboration-app
    spec:
      containers:
        - name: collaboration-app
          image: collaboration-app:v1 # Replace with your actual image
          ports:
            - containerPort: 3000
          # Configure environment variables to ensure connection to shared resources
          env:
            - name: DB_HOST
              value: "postgres-service" # Name of the K8s DB Service
            - name: REDIS_HOST
              value: "redis-service"    # Name of the K8s Redis Service
---
apiVersion: v1
kind: Service
metadata:
  name: collaboration-app-service
spec:
  selector:
    app: collaboration-app
  ports:
    - port: 3000
      targetPort: 3000
  type: LoadBalancer
```
