# constructing-and-using-documentservices

`js-collaboration-ot`中的`DocumentServices`类是服务器端OT（操作转换）功能的核心组件，用于管理文档快照和操作，包括存储、提交和检索。本文将介绍如何构建和使用[DocumentServices](gcdocsite__documentlink?toc-item-id=e04a3031-c69b-4ba3-8926-c2813134ce43)，内容包括：

* 存储和读取文档快照与操作
* 处理操作提交和快照更新
* 添加中间件和钩子扩展

## **应用场景**

* 自定义OT行为
* 优化性能
* 实现特定的持久化解决方案

## 构造方法

`DocumentServices`通过构造函数接受一个配置对象（[IDocConfig](gcdocsite__documentlink?toc-item-id=698211ab-ab28-4131-9a64-c258b4cb148b)），允许开发者自定义数据库和行为参数。

### 配置参数

| 参数名称 | 类型 | 描述 | 默认值 |
| ---- | --- | --- | --- |
| `db` | `IDataBaseAdapter` | 数据库适配器，用于存储快照和操作。 | `MemoryDb` |
| `milestoneDb` | `IMilestoneDataBaseAdapter` | 里程碑数据库适配器，用于定期存储快照。 | 内存实现 |
| `maxSubmitRetries` | `number` | 操作提交的最大重试次数。 | 无限制 |
| `submitSnapshotBatchSize` | `number` | 在将操作应用于当前快照并将更新后的快照提交到数据库之前，累积的操作（ops）数量。 | 100 |

> **关于submitSnapshotBatchSize的说明**：
> 此参数定义了快照更新的频率。当服务器上累积的操作数量达到该值时，这些操作将被应用于当前快照，生成更新后的快照并提交到数据库，从而覆盖旧快照。
> 操作本身是独立存储的，而快照始终保持最新版本。这种机制平衡了快照更新频率与数据库写入开销。

### 示例：基本配置

```typescript
import { DocumentServices, MemoryDb } from '@grapecity-software/js-collaboration-ot';

// 配置DocumentServices
const docService = new DocumentServices({
    db: new MemoryDb(), // 使用内存数据库
    maxSubmitRetries: 3, // 最多重试3次
    submitSnapshotBatchSize: 50 // 累积50个操作后更新快照
});
```

> 默认使用MemoryDb，适用于开发和测试环境。生产环境建议使用持久化适配器（如Postgres Adapter）

## 方法

### use

注册中间件，为操作流程添加自定义逻辑。

```typescript
use<K extends keyof IDocMiddlewareContext<S, T>>(action: K, middleware: IMiddleware<IDocMiddlewareContext<S, T>[K]>)
```

**参数**

* `action`：中间件操作名称（如“submit”、“receive”）
* `middleware`：中间件函数，类型为`IMiddleware`，接收上下文并控制流程。

**示例**

```typescript
docService.use('submit', async (context, next) => {
    console.log('submit op', context.request.op);
});
```

### on

注册钩子，监听操作事件。

```typescript
on<K extends keyof IDocHookContext>(hookName: K, hook: IHook<IDocHookContext[K]>)
```

**参数**

* `hookName`：钩子名称（如“submitRequestEnd”）
* `hook`：钩子函数，类型为`IHook`，接收上下文。

**示例**

```typescript
docService.on('submitRequestEnd', (context) => {
    console.log('Submission completed:', context);
});
```

### fetch

检索指定文档的最新快照。

```typescript
fetch(id: string, context?: IContext): Promise<ISnapshot<S>>
```

**参数**

* `id`：文档ID（字符串）
* `context`（可选）：操作上下文

**返回**
`Promise<ISnapshot<S>>` \- 包含最新快照的Promise。
**示例**

```typescript
const snapshot = await docService.fetch('doc1');
console.log('Latest snapshot:', snapshot.data);
```

### getOps

检索指定文档在某个版本范围内的操作（包含`from`，不包含`to`）。

```typescript
getOps(id: string, from: number, to?: number, context?: IContext): Promise<IOp<T>[]>
```

**参数**

* `id`：文档ID（字符串）
* `from`：起始版本号（包含）
* `to`（可选）：结束版本号（不包含）
* `context`（可选）：操作上下文

**返回**
`Promise<IOp<T>[]>` \- 包含操作数组的Promise。
**示例**

```typescript
const ops = await docService.getOps('doc1', 0, 5);
console.log(ops);
```

### submit

向指定文档提交操作。

```typescript
submit(id: string, op: IOp<T>, context?: IContext): Promise<IOp<T>[]>
```

**参数**

* `id`：文档ID（字符串）
* `op`：操作，类型为`IOp<T>`
* `context`（可选）：操作上下文

**返回**
`Promise<IOp<T>[]>` \- 解析为结果操作的Promise。
**示例**

```typescript
docService.submit('doc1', op);
```

### fetchHistorySnapshot

检索指定文档的历史快照。

```typescript
fetchHistorySnapshot(id: string, version?: number, context?: IContext): Promise<ISnapshot<S>>
```

**参数**

* `id`：文档ID（字符串）
* `version`（可选）：目标版本号；若省略，返回最新快照
* `context`（可选）：操作上下文

**返回**
`Promise<ISnapshot<S>>` \- 包含历史快照的Promise。
**示例**

```typescript
const snapshot = await docService.fetchHistorySnapshot('doc1', 2);
console.log('Historical snapshot:', snapshot.data);
```
