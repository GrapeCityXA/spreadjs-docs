# server-middleware

**中间件**是服务器处理连接和消息的关键机制，用于在事件（如连接建立或消息接收）到达钩子之前执行自定义逻辑。服务器本身不包含业务逻辑，而是依赖中间件来实现特定功能。服务器提供的中间件机制允许开发者**自定义处理连接和消息的逻辑**。本文档介绍其用法和特性。

## **应用场景**

* 用户认证
* 权限验证
* 日志管理

## 注册

使用 [server.use](gcdocsite__documentlink?toc-item-id=c94e9589-dfdf-4066-af97-776d49d2506e#use) API 注册中间件，支持两种用法：

### 1\. 单个注册

```typescript
server.use('connect', async (context, next) => {
    console.log('客户端连接中:', context.connection.id);
    await next();
});
server.use('message', async (context, next) => {
    console.log('收到消息:', context.data);
    await next();
});
```

### 2\. 批量注册

```typescript
server.use({
    connect: async (context, next) => {
        console.log('客户端连接中:', context.connection.id);
        await next();
    },
    message: async (context, next) => {
        console.log('收到消息:', context.data);
        await next();
    }
});
```

## 执行顺序

多个已注册的中间件将按注册顺序执行。

```typescript
server.use('connect', (context, next) => {
    console.log('中间件1');
    await next();
});
server.use('connect', (context, next) => {
    console.log('中间件2');
    await next();
});
server.use('connect', (context, next) => {
    console.log('中间件3');
    await next();
});
server.on('connect', () => {
    console.log('钩子');
});
// 输出
//中间件1
//中间件2
//中间件3
// 钩子
```

## 错误处理

如果使用 `error` 参数调用 `next` 方法，将发生以下情况：

* 停止执行后续中间件。
* 触发服务器内置的错误处理程序，将错误返回给客户端，同时触发客户端的 `error` 事件。
* 对于 `connect` 中间件，连接请求会被拒绝（由于连接尚未建立，因此不会触发 connect 钩子）。

```typescript
// 服务端
server.use('connect', async (context, next) => {
    console.log('中间件1');
    await next();
});
server.use('connect', async (context, next) => {
    console.log('中间件2');
    await next(new Error('测试中间件错误'));
});
server.use('connect', async (context, next) => {
    console.log('中间件3');
    await next();
});
server.on('connect', () => {
    console.log('钩子');
});

// 输出:
//中间件1
//中间件2
```

### **客户端接收错误**

```typescript
// 客户端
connection.on('error', (error) => {
    console.log(error.message); // 输出 "测试中间件错误"
});
```

## 短路处理

如果中间件内未调用 `next()` 函数：

* 停止执行后续中间件，事件处理流程将终止。
* 对于 `connect` 中间件，必须始终调用 `next()`，否则连接请求将保持挂起状态，直到超时关闭。
* 对于 `message` 中间件，可使用短路处理提前终止处理流程。

```typescript
// 服务端
server.use('message', async (context, next) => {
    console.log('中间件1');
    await next();
});
server.use('message', async (context, next) => {
    console.log('中间件2');
    // 短路：未调用 next()
});
server.use('message', async (context, next) => {
    console.log('中间件3');
    await next();
});
server.on('message', () => {
    console.log('钩子');
});

// 输出:
// 中间件1
// 中间件2
```

## 接口定义

```typescript
export interface IMiddlewares {
    connect?: IMiddleware<IConnectMiddlewareContext>;  // 连接时
    message?: IMiddleware<IMessageMiddlewareContext>;  // 接收客户端消息时
}
```
