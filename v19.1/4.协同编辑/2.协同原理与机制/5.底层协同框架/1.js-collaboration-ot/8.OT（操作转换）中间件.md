# ot-middleware

`js-collaboration-ot` 中的中间件机制允许开发者拦截并自定义服务器端 OT（操作转换）处理流程中的逻辑，例如权限验证或日志记录。本文将介绍如何使用中间件，包括其生命周期、注册方法和实际示例。

## 基本概念

中间件是 `DocumentServices` 的核心扩展功能，用于在操作（`op`）和快照（`snapshot`）的处理阶段**添加自定义逻辑**。
**目的**：

* 拦截并验证操作流程
* 修改上下文或终止处理

**适用场景**：用户认证、数据验证、日志记录、性能监控等。
**与钩子的区别**：中间件可以中断流程并返回错误，而钩子仅监听事件。

## 生命周期

中间件覆盖 OT 处理流程的多个阶段，每个阶段对应一个操作（action）。开发者可选择性介入这些阶段。以下是支持的中间件操作及其触发时机：

| 操作 | 描述 |
| --- | --- |
| `receive` | 服务器接收客户端消息时触发，用于初始验证或日志记录。 |
| `submit` | 操作（`op`）即将提交时触发，可用于验证操作数据。 |
| `apply` | 操作即将应用到快照时触发（快照仍为旧状态）。 |
| `commit` | 操作即将提交至数据库时触发（操作已转换后），可用于最终验证。 |
| `afterWrite` | 操作成功写入数据库后触发，用于后续处理或通知。 |
| `readSnapshots` | 从数据库加载一个或多个快照时触发（如 `fetch` 或 `subscribe` ,可用于阻止某个快照被读取。） |
| `readOp` | 从数据库加载操作时触发，可拒绝操作读取。 |
| `reply` | 文档即将向客户端发送非错误回复时触发。 |

## 中间件函数

中间件是异步函数，接收 `context` 和 `next` 参数：

* `context`：包含当前操作的上下文信息（如 `connection`、`request`）。
* `next`：继续执行的函数，可传入错误以终止流程。
    * `await next()`：继续执行后续中间件或处理逻辑。
    * `await next(error)`：终止流程并返回错误。

### 示例：基础中间件

```typescript
docService.use('submit', async (context, next) => {
    const user = context.connection.tags.get('user');
    if (user.role === 'editor') {
        console.log('提交操作:', context.request.op);
        await next(); // 继续
    } else {
        await next('无权限'); // 终止
    }
});
```

## 注册中间件

使用 `DocumentServices` 的 [use ](gcdocsite__documentlink?toc-item-id=e04a3031-c69b-4ba3-8926-c2813134ce43#use)方法注册中间件：

```typescript
import { DocumentServices } from '@grapecity-software/js-collaboration-ot';

const docService = new DocumentServices();

docService.use('receive', async (context, next) => {
    console.log('收到消息:', context.request);
    await next();
});
```

## 中间件执行顺序

同一操作的多个中间件按注册顺序执行。若某个中间件调用 `next(error)`，后续中间件将被跳过。

### 示例：执行顺序

```typescript
docService.use('submit', async (context, next) => {
  console.log('中间件 1');
  await next();
});
docService.use('submit', async (context, next) => {
  console.log('中间件 2');
  await next();
});
docService.use('submit', async (context, next) => {
  console.log('中间件 3');
  await next();
});
// 输出：
// 中间件 1
// 中间件 2
// 中间件 3
```

### 示例：错误处理

```typescript
docService.use('submit', async (context, next) => {
    console.log('中间件 1');
    await next();
});
docService.use('submit', async (context, next) => {
    console.log('中间件 2');
    await next('测试错误');
});
docService.use('submit', async (context, next) => {
    console.log('中间件 3'); // 不会执行
    await next();
});
// 输出：
// 中间件 1
// 中间件 2
// 错误返回给客户端，触发客户端错误事件
```

## 应用场景

以下是常见的中间件应用场景及实现：

### 1\. 权限验证

```typescript
docService.use('submit', async (context, next) => {
    const user = context.connection.tags.get('user');
    if (user.role === 'editor') {
        console.log('提交操作:', context.request.op);
        await next(); // 继续
    } else {
        await next('无权限'); // 终止
    }
});
```

### 2\. 日志记录

```typescript
docService.use('afterWrite', async (context, next) => {
    console.log('操作写入数据库:', context.request.op);
    await next();
});
```

## 总结

中间件为 `js-collaboration-ot` 服务器端提供了强大的流程控制能力。通过在不同生命周期阶段注册中间件，可实现验证、日志记录等功能。
