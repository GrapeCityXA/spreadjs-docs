# performance-and-calculation

大型`SJS.TABLE`公式会大幅增加重新计算耗时，原因是系统需要为每一组输入组合执行多次模拟运算。
SpreadJS 提供了多种计算模式与进度事件，助力开发者管控程序运行性能。

## 计算模式

默认情况下，当依赖数据发生变动时，SpreadJS 会自动重新计算所有公式。
对于搭载海量数据表的工作簿，可通过`CalculationMode`调整公式计算规则。

```javascript
spread.options.calculationMode = GC.Spread.Sheets.CalculationMode.partial;
```

手动触发重新计算的写法：

```javascript
spread.calculate();
```

>type=info
> **注意事项：**
>
> * 导入包含大型数据表的工作簿时，建议启用局部计算模式。若不开启，所有`SJS.TABLE`公式会在文件加载完成后立即执行重算，极易出现明显卡顿延迟。
> * 开启局部计算模式后，依赖数据变动时，除`SJS.TABLE`以外的所有公式会自动重算；`SJS.TABLE`公式仅在调用`spread.calculate()`方法时才会执行重算。

## 监听计算进度

SpreadJS 会触发`CalculationProgress`事件，用来实时反馈公式重算进度。

### 开启增量计算（通用公式适用）

针对普通公式的重算流程，开启增量计算后即可启用进度上报功能：

```javascript
spread.options.incrementalCalculation = true;
```

功能开启后，`CalculationProgress`事件可返回以下信息：

* 总单元格数量`totalCells`
* 待计算单元格数量`pendingCells`
* 迭代计算标识`iterate`

## `SJS.TABLE`专属进度上报机制

`SJS.TABLE`拥有独立的进度上报逻辑。

### 事件触发规则

执行`SJS.TABLE`运算过程中，会触发`CalculationProgress`事件，规则如下：

* 即便未开启增量计算`incrementalCalculation`，该事件依旧可以触发
* 该事件独立于普通公式的重算进度，互不干扰

当工作簿内存在`SJS.TABLE`数据表时，事件触发流程：

1. 系统检测到需要运算`SJS.TABLE`时，率先触发事件，此时`dataTableProgress`数值为0
2. 运算进行期间，事件持续触发，通过`dataTableProgress`数值展示数据表的计算进度

### 事件传参规则

在`SJS.TABLE`运算阶段：

* 事件回调参数中会携带`dataTableProgress`进度字段
* 不再返回总单元格数、待计算单元格数、迭代计算等通用进度字段
    `dataTableProgress`用于表示数据表计算任务的完成占比。

### 代码示例

```javascript
spread.bind(GC.Spread.Sheets.Events.CalculationProgress, function (e, info) {
    if (info.dataTableProgress !== undefined) {
        console.log('数据表进度：' + (info.dataTableProgress * 100).toFixed(0) + '%');
        return;
    }
    if (info.pendingCells === 0) {
        console.log('计算任务已完成');
    }
});
```

这种进度区分设计，既能避免大型`SJS.TABLE`模拟运算产生大量冗余的通用计算完成通知，又能精准展示数据表运算的实时进度。

## 状态栏进度提示

执行`SJS.TABLE`计算时，SpreadJS 内置状态栏会自动展示如下进度提示，无需额外配置：

```auto
数据表：x%
```

可直观让用户知晓当前正处于数据表计算进程中。
