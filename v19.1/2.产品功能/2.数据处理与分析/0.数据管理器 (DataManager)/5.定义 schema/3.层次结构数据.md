# hierarchical-data

表 schema 中的 `hierarchy` 属性用于在单个表内启用层次结构（树形结构）数据建模。
配置 hierarchy 后：

* 记录会组织为父子关系。
* 表会被解释为树，而不是扁平列表。
* 层次结构会从记录数据中推导。
* 已存储的数据不会被复制或转换。

Hierarchy 是 schema 级结构配置。
它不会引入跨表关系。

## 基本结构

Hierarchy 定义在表 schema 中：

```typescript
interface ISchemaOption {
    hierarchy?: IHierarchyOption;
}
```

```typescript
interface IHierarchyOption {
    type: 'Parent' | 'ChildrenPath' | 'Level' | 'Custom';
    column: string;
    outlineColumn?: string | IHierarchyOutlineColumnOptions;
    summaryFields?: { [field: string]: string };
    parse?: (options) => any;
    unparse?: (options) => any;
}
```

该配置指定如何从记录字段推导父子关系。

## 支持的层次结构类型

层次结构行为取决于 `type` 属性。

### Parent 类型

记录同时包含：

* 主键字段
* 父级引用字段

示例数据：

```json
[
  { id: 1, parentId: -1 },
  { id: 2, parentId: -1 },
  { id: 3, parentId: 1 }
]
```

配置：

```javascript
schema: {
    hierarchy: {
        type: "Parent",
        column: "parentId"
    },
    columns: {
        id: { isPrimaryKey: true },
        parentId: {}
    }
}
```

`column` 用于标识引用父记录的字段。
主键用于唯一标识节点，因此是必需的。

### Level 类型

层次结构由以下内容决定：

* 层级指示字段
* 记录顺序

示例：

```json
[
  { name: "USA", level: -1 },
  { name: "Texas", level: 0 },
  { name: "Houston", level: 1 }
]
```

配置：

```javascript
hierarchy: {
    type: "Level",
    column: "level"
}
```

level 值决定每条记录相对于相邻记录的深度。
主键不是必需的，但建议配置。

### ChildrenPath 类型

记录包含嵌套的子记录集合。
示例：

```json
[
  {
    name: "USA",
    children: [
      { name: "Texas" }
    ]
  }
]
```

配置：

```javascript
hierarchy: {
    type: "ChildrenPath",
    column: "children"
}
```

`column` 指定包含子记录的属性。

### Custom 类型

层次结构由自定义解析规则推导。
示例：

```json
[
  { id: "1" },
  { id: "1.1" },
  { id: "1.1.1" }
]
```

配置：

```javascript
hierarchy: {
    type: "Custom",
    column: "id",
    parse: function (options) {
        const segments = options.data.id.split(".");
        return segments.slice(0, -1).join(".");
    }
}
```

`parse` 函数会从每条记录中推导父级键。
可选的 `unparse` 函数可以定义新键的生成方式。

## 汇总字段

Hierarchy 支持为父记录配置汇总字段。

```javascript
hierarchy: {
    type: "Parent",
    column: "parentId",
    summaryFields: {
        budget: '=SUM(CHILDREN(1,"budget"))'
    }
}
```

汇总字段：

* 将公式应用到父记录
* 仅当记录具有子记录时才会计算
* 覆盖汇总字段的可编辑行为

这些公式会在计算期间求值，不会更改已存储的子记录值。

## 大纲列

大纲列定义在兼容视图中渲染时，由哪一列以视觉方式表示树形结构。
可以通过以下方式指定：

* 在 `hierarchy.outlineColumn` 中指定
* 或在列/视图级别指定

当两者同时定义时：

* 视图级配置会覆盖 schema 级设置。

Hierarchy 配置本身不渲染 UI。
它只提供结构元数据。

## 结构约束

层次结构建模可能需要：

* 主键（`Parent` 类型需要，`Custom` 类型通常也需要）
* 用于稳定重排序的数值型 `rowOrder` 列（如果使用它的视图支持）

Hierarchy 不会：

* 创建跨表关系
* 修改远程同步语义
* 复制记录

它只会重构记录在表内部的解释方式。

## 职责边界

Hierarchy 是 schema 级数据结构配置。
它：

* 在单个表内定义父子关系
* 影响计算上下文和结构解释
* 由支持层次结构渲染的视图使用

视图特定操作（例如展开、折叠或重排序）会在其他文档中单独说明。
这种分离可以确保数据结构与 UI 行为保持解耦。
