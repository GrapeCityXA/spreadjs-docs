# defining-columns

表 schema 定义原始数据在 DataManager 中如何被解释和管理。
在 schema 中，列是核心建模单元。
每个列都描述记录中的某个字段在表中的行为。
列不是 UI 元素。
列是数据建模定义，用于决定标识、类型、行为和展示元数据。

## 从记录到列

当数据加载到表中时，数据源中的每个对象都会成为一条记录（行）。

```javascript
const table = dataManager.addTable("orders", {
    data: [
        { id: 1, price: 10, quantity: 2 }
    ],
    schema: {
        columns: {
            id: { dataType: "number", isPrimaryKey: true },
            price: { dataType: "number" },
            quantity: { dataType: "number" },
            total: {
                dataType: "formula",
                value: "=[@price] * [@quantity]"
            }
        }
    }
});
```

在此示例中：

* `id` 定义记录标识。
* `price` 和 `quantity` 定义带类型的字段。
* `total` 是由其他字段推导出的计算列。

如果未定义列，字段会使用默认行为进行解释。
通过显式定义列，可以控制数据的结构化和管理方式。

## 列定义可以控制什么

列定义可以指定：

* 字段如何映射到原始数据
* 字段值如何解析并设置类型
* 字段是否唯一标识一条记录
* 字段是否为计算型或事件驱动型
* 验证和索引行为
* 默认展示元数据

为了保持职责清晰，列配置分为以下类别：

### [核心结构设置](gcdocsite__documentlink?toc-item-id=8e4cd093-cdf2-409a-b941-4eb4e8c0753a)

定义标识和结构映射。
示例包括：

* 列名和数据映射
* `dataType`
* `isPrimaryKey`
* 基于公式的值定义

这些设置决定记录在结构层面如何被解释。

### [数据行为设置](gcdocsite__documentlink?toc-item-id=c5338f46-e055-44e7-a101-6617b3c5f0f2)

控制列值在解析后的行为。
示例包括：

* 必填和只读规则
* 默认值
* 解析模式
* 索引
* null 和空值的显示替代内容

这些设置会影响验证、规范化和性能。

### [高级数据设置](gcdocsite__documentlink?toc-item-id=6d3a81dd-7679-4257-a242-8a3aa4c47f6a)

启用动态行为和关系行为。
示例包括：

* 公式列
* 触发器公式
* 查找定义
* 感知关系的能力

这些设置会引入计算能力和受控值域。

### [样式与 UI 元数据](gcdocsite__documentlink?toc-item-id=3fd6c196-27c4-4fe8-b2e7-af0bb753e64c)

定义由视图渲染时的默认展示行为。
示例包括：

* 标题和宽度
* 单元格样式和表头样式
* 条件格式
* 验证规则
* 交互控件

这些设置不会修改已存储的数据。
它们提供视图可以使用并覆盖的基础元数据。

## 职责边界

列定义属于表 schema。
它们：

* 建模数据在 DataManager 中的行为
* 独立于具体 UI 实现

[视图](gcdocsite__documentlink?toc-item-id=1b947650-5bd3-432b-a78e-27648ad6945e) 会使用列元数据来渲染数据。
视图级配置可以覆盖展示相关设置，而不会改变 schema。
这种分离可以确保数据建模与展示在文档体系和产品架构中保持解耦。
