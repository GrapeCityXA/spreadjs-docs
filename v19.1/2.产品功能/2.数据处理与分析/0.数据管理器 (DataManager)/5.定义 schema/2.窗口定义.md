# window-definition

表 schema 的 `window` 属性用于定义可复用的窗口规范，供 [`WINDOW()`](gcdocsite__documentlink?toc-item-id=e64b9e1c-e500-4ea7-a0d4-779227b33a0a) 公式使用。
窗口定义：

* 属于表 schema
* 不修改已存储的数据
* 不影响远程操作
* 不改变列结构
* 作为公式计算时使用的命名窗口配置

它们提供了一种简写机制，使窗口规范只需定义一次，即可在多个计算中复用。

## 为什么在 schema 中定义窗口

使用 `WINDOW()` 公式时，表达式经常会重复出现：

* `PARTITIONBY`
* `ORDERBY`
* 框架定义（`FRAMEROWS`、`FRAMERANGE`、`FRAMEGROUPS`）

无需在每个公式中重复这些表达式，可以在 schema 中定义命名窗口，并通过名称引用它。
这可以提升：

* 可读性
* 可维护性
* 多个计算之间的一致性

## 基本结构

`window` 属性定义为键值集合。

```typescript
interface ISchemaOption {
    window?: {
        [name: string]: string;
    };
}
```

每个键都是窗口名称。
每个值都是一个 `WINDOWDEF` 公式表达式。

## 定义基础窗口

示例：

```javascript
dataManager.addTable("orders", {
    schema: {
        window: {
            YearPartition:
                '=WINDOWDEF(PARTITIONBY([Product], YEAR([@OrderDate])))',
            RunningFrame:
                '=WINDOWDEF(PARTITIONBY([Product]), ORDERBY([@OrderDate]), FRAMEROWS(-1, [@]))'
        }
    }
});
```

每个定义会指定：

* 分区逻辑
* 可选的排序逻辑
* 可选的框架逻辑

定义本身不会执行聚合。
它只定义窗口上下文。

## 使用命名窗口

可以在 `WINDOW()` 公式中引用命名窗口：

```javascript
=WINDOW(SUM([Sales]), "YearPartition")
```

命名窗口会提供：

* `PARTITIONBY`
* `ORDERBY`
* 框架配置

聚合函数（例如 `SUM`）仍然在 `WINDOW()` 调用中指定。

## 窗口链式引用

窗口链式引用允许复用先前定义的窗口，并对其中一部分进行覆盖。
当命名窗口与额外窗口子句一起引用时：

* `WINDOW()` 调用中提供的表达式会覆盖基础窗口中的对应部分。
* 未指定的部分会继承基础窗口的设置。

示例：

```javascript
// 完整复用基础窗口
WINDOW(SUM([Sales]), "YearPartition")

// 覆盖 ORDERBY
WINDOW(SUM([Sales]), "YearPartition",
       ORDERBY([@OrderDate]))

// 仅覆盖框架
WINDOW(SUM([Sales]), "YearPartition",
       FRAMEROWS([@-2], [@]))
```

覆盖规则：

* 调用中定义的 `PARTITIONBY`、`ORDERBY` 和框架表达式会替换基础窗口中的对应部分。
* 未显式提供的任何部分都会保持不变。

这样既能灵活复用，又能集中管理窗口定义。

## 框架类型和排除模式

窗口定义可以包含以下框架表达式：

* `FRAMEROWS`
* `FRAMERANGE`
* `FRAMEGROUPS`

框架表达式可以选择包含排除模式。
这些语法属于窗口函数语言的一部分，并会在公式计算期间求值。
DataManager 为窗口函数提供基础支持。有关 TableSheet 中的详细用法和配置，请参阅 [TableSheet 窗口函数文档](gcdocsite__documentlink?toc-item-id=e64b9e1c-e500-4ea7-a0d4-779227b33a0a)。本页仅关注 schema 级别的窗口配置。

## 职责边界

窗口定义：

* 使用可复用窗口规范扩展 schema
* 仅影响公式计算
* 不更改已存储的记录
* 不参与数据同步
* 不引入表之间的关系

它们是 DataManager schema 中的公式基础设施机制。
这样可以在以下内容之间保持清晰分离：

* 数据结构（列和关系）
* 公式语义（窗口行为）
* 视图渲染
