# core-structure-settings

创建表时，数据源中的每条记录都会成为表中的一行。
`schema.columns` 部分定义记录中的每个字段如何建模为表列。
例如：

```javascript
const table = dataManager.addTable("employees", {
    data: [
        { id: 1, name: "Alice", birthday: "2000-01-01" },
        { id: 2, name: "Bob", birthday: "2001-05-12" }
    ],
    schema: {
        columns: {
            id: { dataType: "number", isPrimaryKey: true },
            name: { dataType: "string" },
            birthday: { dataType: "date" }
        }
    }
});
```

在此示例中：

* `data` 中的每个对象都是一条记录。
* 记录的每个属性（`id`、`name`、`birthday`）都会成为一列。
* `columns` 配置定义 DataManager 如何解释和管理这些字段。

核心结构设置定义：

* 列如何映射到原始数据
* 列值如何解析
* 列类型如何解释
* 列是否唯一标识一条记录

它们构成列建模的结构基础。

## 列名

`schema.columns` 中的每个条目都表示一个列定义。

```javascript
schema: {
    columns: {
        id: { dataType: "number" },
        name: { dataType: "string" }
    }
}
```

对象键（`id`、`name`）是列在表中的逻辑标识。
该名称会用于：

* 在公式中引用字段
* 定义关系
* 访问行数据
* 构建视图

如果在列定义中指定了 `name` 属性，它会覆盖对象键，作为内部列名。
在大多数情况下，使用对象键即可。

## dataName

`dataName` 会将列映射到原始数据中的另一个字段名。

```javascript
schema: {
    columns: {
        firstName: {
            dataName: "salesperson"
        }
    }
}
```

在此示例中：

* `salesperson` 是原始数据中的字段
* `firstName` 成为表中的列名

它适用于以下场景：

* 后端字段名与前端命名约定不一致
* 需要重命名多个字段以提升清晰度
* 同一数据源需要在不同逻辑模型中复用

`dataName` 不会修改原始数据。
它只定义解析期间如何映射字段。

## value

`value` 属性定义列值的解析方式。
它可以是：

* 字段名
* 公式表达式

### 字段映射

```javascript
columns: {
    name: {
        value: "username",
    }
}
```

这会将列显式映射到记录中的特定字段。
如果未定义 `value`，默认使用列名作为字段名。

### 公式列

如果 `value` 包含公式表达式，并且 `dataType` 设置为 `"formula"`，该列会成为计算列。

```javascript
TotalUnits: {
    dataType: "formula",
    value: "=[@UnitsInStock] + [@UnitsOnOrder]"
}
```

在这种情况下：

* 该列不会直接映射到原始数据字段
* 它的值由同一记录中的其他字段计算得出

公式列完成计算后，其行为类似普通数据列。

## dataType

`dataType` 定义列值的解释方式。
常见类型包括：

* `"string"`
* `"number"`
* `"boolean"`
* `"date"`
* `"formula"`
* `"object"`
* `"array"`

数据类型会影响：

* 值解析（尤其是日期和数字）
* 公式行为
* 验证逻辑
* 与视图的集成

例如，当 JSON 数据包含日期字符串时：

```javascript
columns: {
    birthday: {
        dataType: "date"
    }
}
```

解析期间，该值会转换为日期值。
如果未指定 `dataType`，类型会根据值推断。

## isPrimaryKey

`isPrimaryKey` 将列标记为表主键的一部分。

```javascript
columns: {
    id: {
        isPrimaryKey: true
    }
}
```

主键：

* 唯一标识每条记录
* 是关系所必需的
* 是某些高级功能（例如跨视图）所必需的

主键约束会在表级别强制执行。
如果多个列被标记为 `isPrimaryKey`，它们会组成复合键。

## 结构职责

核心结构设置定义：

* 列如何映射到原始数据
* 列值如何计算
* 列类型如何解释
* 列是否唯一标识记录

它们不控制：

* 验证规则
* 显示格式
* 筛选行为
* 样式

这些能力需要在其他列建模章节中单独配置。
