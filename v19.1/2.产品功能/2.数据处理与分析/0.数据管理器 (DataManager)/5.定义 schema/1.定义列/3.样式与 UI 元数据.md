# style-ui-metadata

样式与 UI 元数据定义列被视图实现使用时如何展示。
这些设置：

* 不修改已存储的数据
* 不影响记录结构
* 不参与解析或索引

它们描述列数据在表格视图中应如何渲染或交互。
虽然这些属性定义在表 schema 中，但只有当视图（例如 TableSheet 视图）使用列定义时才会应用。

## caption

定义列的表头文本。

```javascript
columns: {
    name: {
        caption: "Employee Name"
    }
}
```

如果未指定，则使用列名作为默认标题。
`caption` 只影响展示。

## width

定义列在视图中渲染时的默认宽度。

```javascript
columns: {
    name: {
        width: 150
    }
}
```

宽度可以是：

* 数字形式的像素值
* 星号尺寸字符串（取决于视图支持）

宽度不会影响已存储的数据。
有关布局行为详情，请参阅 [视图列配置](gcdocsite__documentlink?toc-item-id=b4cd0e67-24dd-4b5a-b91e-086b046881a0)。

## style

定义列的默认单元格样式。

```javascript
columns: {
    price: {
        style: { formatter: "$#,##0.00" }
    }
}
```

样式选项可以包括：

* 格式化器
* 对齐方式
* 字体
* 背景色
* 单元格类型（取决于视图支持）

样式配置由视图层使用。

## headerStyle

定义表头单元格样式。

```javascript
columns: {
    orderId: {
        headerStyle: {
            backColor: "#3390FF",
            font: "bold 14px Calibri"
        }
    }
}
```

表头样式只应用于列头，并依赖具体视图。

## conditionalFormats

定义应用于列的条件格式规则。

```javascript
columns: {
    price: {
        conditionalFormats: [rule]
    }
}
```

条件格式：

* 根据单元格值应用样式
* 由视图层计算
* 不更改底层数据

## validator

定义应用于列的验证规则。

```javascript
columns: {
    quantity: {
        validator: {
            type: "number",
            comparisonOperator: "greaterThan",
            value1: 0
        }
    }
}
```

验证器：

* 强制执行输入约束
* 可以提供错误消息
* 在编辑操作期间计算

除非输入被拒绝，否则验证逻辑不会改变已存储的值。
有关高级验证行为，请参阅 [数据验证](gcdocsite__documentlink?toc-item-id=1342cf86-5473-4687-b68e-359a0f5d5e19)。

## allowSort, allowFilterByValue, allowFilterByList

控制视图中排序和筛选能力的可见性与可用性。

```javascript
columns: {
    orderId: {
        allowSort: false,
        allowFilterByValue: false,
        allowFilterByList: false
    }
}
```

这些设置：

* 影响视图交互行为
* 不影响 DataManager 中的底层查询逻辑

## headerFit

定义某些视图实现中列头的布局方式。

```javascript
columns: {
    orderId: {
        headerFit: "stack"
    }
}
```

支持的模式取决于视图实现。
headerFit 只影响布局。

## outlineColumn

在支持层次结构显示的视图中，将列标记为大纲列。

```javascript
columns: {
    name: {
        outlineColumn: true
    }
}
```

当在 schema 级别配置层次结构数据时，此属性才有意义。
层次结构建模请参阅单独的 [层次结构数据](gcdocsite__documentlink?toc-item-id=a118e238-657b-40a3-aa1d-f45685caefec) 文档。

## Schema 级配置与视图级配置

样式与 UI 元数据可以定义在以下两个级别：

* 表 schema 级别
* 视图列级别

当两者同时存在时：

* 视图级配置会覆盖 schema 级默认值
* schema 级设置会作为基础元数据

这种分离可以确保：

* 数据建模保持独立于视图
* 展示逻辑可以在不同视图之间变化
* schema 定义可以复用

## 职责边界

样式与 UI 元数据：

* 描述默认展示行为
* 由视图使用
* 不改变数据
* 不影响解析或关系
