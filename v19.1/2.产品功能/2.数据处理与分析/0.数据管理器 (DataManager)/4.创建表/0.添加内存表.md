# add-memory-table

内存表会将数据存储在客户端本地。
调用 [`addTable`](gcdocsite__documentlink?toc-item-id=d168d582-7001-4e98-a184-2aafa89215e1#addtable) 时，可以通过 `data` 选项直接提供数据。
所有操作都在内存中完成。
不会涉及服务器通信。
内存表适用于：

* 静态数据集
* 客户端应用
* 原型开发场景
* 离线用例

## 创建内存表

使用 [`IDataSourceOption`](gcdocsite__documentlink?toc-item-id=24e07bc4-c7cc-407c-98d5-0670ccab2cce#idatasourceoption) 的 `data` 属性：

```javascript
const dataManager = spread.dataManager();

const table = dataManager.addTable("employees", {
    data: [
        { id: 1, name: "Alice", age: 24 },
        { id: 2, name: "Bob", age: 26 },
        { id: 3, name: "Cindy", age: 25 }
    ]
});
```

此时表已经定义，但尚未初始化。

## 必要初始化

创建表后，调用：

```javascript
table.fetch();
```

虽然数据已经在本地可用，但调用 [`fetch()`](gcdocsite__documentlink?toc-item-id=f2382678-7491-4d87-8523-09bfc84e5b68#fetch) 可以确保：

* 内部数据状态完成初始化
* 应用 schema 处理（如果已定义）
* 表已准备好用于创建视图

示例：

```javascript
table.fetch().then(function () {
    const view = table.addView("defaultView");
});
```

所有表类型在执行进一步操作前都需要调用 `fetch()`。

## 提供数据格式

`data` 选项支持多种格式：

* JSON 数组（默认）
* CSV 字符串
* XML 字符串

如果 `data` 是 JSON 数组，则不需要额外配置。

### JSON（默认）

```javascript
const table = dataManager.addTable("employees", {
    data: [
        { id: 1, name: "Alice", price: 24 },
        { id: 2, name: "Bob", price: 26 },
        { id: 3, name: "Cindy", age: 25 }
    ]
});
```

JSON 是默认数据类型。
如果未指定 `schema.type`，会按 `"json"` 处理。

### CSV

以字符串形式提供 CSV 数据时，必须指定：

```javascript
schema: {
    type: "csv"
}
```

示例：

```javascript
const table = dataManager.addTable("employees", {
    data: `id,name,price
1,Alice,24
2,Bob,26
3,Cindy,25`,
    schema: {
        type: "csv"
    }
});
```

>type=note
> 如果没有 `schema.type = "csv"`，该字符串会被视为普通 JSON 值，不会进行解析。

### XML

提供 XML 数据时，必须指定：

* `schema.type = "xml"`
* `schema.dataPath`（如果集合是嵌套的）

示例：

```javascript
const table = dataManager.addTable("employees", {
    data: `
<root>
    <row>
        <id>1</id>
        <name>Alice</name>
        <price>24</price>
    </row>
    <row>
        <id>2</id>
        <name>Bob</name>
        <price>26</price>
    </row>
    <row>
        <id>3</id>
        <name>Cindy</name>
        <price>25</price>
    </row>
</root>
`,
    schema: {
        type: "xml",
        dataPath: "root.row"
    }
});
```

说明：

* `type: "xml"` 启用 XML 解析。
* `dataPath` 指定记录集合所在的位置。
* 如果未指定 `dataPath`，会返回整个解析后的对象。

## 内存表中的 schema

在内存表中，`schema` 主要有两个用途：

1. 数据解析（使用 CSV 或 XML 时）
2. 列建模和数据行为

如果未提供 schema：

* JSON 数据会自动推断
* 列会从对象键生成

Schema 配置请参阅 [Schema](gcdocsite__documentlink?toc-item-id=fe5a35c4-1f4e-4c43-b46a-d456ae391767) 章节。
本节演示内存表中的典型用法。

### 解析行为

`schema.type` 属性决定如何解析 `data` 字符串：

| schema.type | 预期数据格式 |
| ----------- | -------------------- |
| json（默认） | JSON 数组 |
| csv | CSV 字符串 |
| xml | XML 字符串 |
| columnJson | 基于列的 JSON 结构 |

如果提供字符串但未设置 `schema.type`，它会按 `"json"` 处理，不会作为 CSV 或 XML 解析。

### 列建模

Schema 可以定义列结构和数据类型：

```javascript
const table = dataManager.addTable("orders", {
    data: [
        { id: 1, orderDate: "2025-01-01" }
    ],
    schema: {
        columns: {
            orderDate: {
                dataType: "date"
            }
        }
    }
});
```

列定义允许：

* 数据类型转换
* 格式化行为
* 主键定义
* 高级列配置

### 展开嵌套字段

如果字段包含嵌套对象，可以使用 `spread` 将其展开为多个列。
示例：

```javascript
const table = dataManager.addTable("sales", {
    data: [
        {
            id: 1,
            address: {
                country: "USA",
                state: "California",
                city: "San Francisco",
                postalCode: "94105"
            }
        },
        {
            id: 2,
            address: {
                country: "Germany",
                state: "Berlin",
                city: "Berlin",
                postalCode: "10115"
            }
        }
    ],
    schema: {
        columns: {
            address: {
                spread: true
            }
        }
    }
});
```

`fetch()` 之后，嵌套字段会成为单独的列。
这可以将结构化数据扁平化，供视图使用。

## 导出和导入

内存表支持通过以下格式导出和导入：

* JSON
* SJS

由于数据完全驻留在内存中，因此支持完整序列化。
