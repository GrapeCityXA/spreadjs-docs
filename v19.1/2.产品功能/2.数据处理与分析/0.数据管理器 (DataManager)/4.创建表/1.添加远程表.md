# add-remote-table

远程表会从服务器获取数据，并可以选择将变更同步回服务器。
与内存表不同，远程表在执行 [`fetch()`](gcdocsite__documentlink?toc-item-id=f2382678-7491-4d87-8523-09bfc84e5b68#fetch) 之前不包含数据。
远程表支持：

* 服务端数据加载
* 数据同步（单次或批量模式）
* Schema 映射
* 多种响应协议

## 基本远程表（只读）

远程表的最低要求是配置 `read`。
以下示例使用标准化的 `products` 数据集：

```javascript
const dataManager = spread.dataManager();

const products = dataManager.addTable("products", {
    remote: {
        read: {
            url: "https://demodata.grapecity.com/northwind/api/v1/products",
            method: "GET"
        }
    }
});
```

此时表结构已经定义，但还不包含任何记录。

## 必要初始化

所有表在执行进一步操作前都必须调用 [`fetch()`](gcdocsite__documentlink?toc-item-id=f2382678-7491-4d87-8523-09bfc84e5b68#fetch)。

```javascript
orders.fetch();
```

如果未调用 `fetch()`，表会保持为空。
示例：

```javascript
orders.fetch().then(function () {
    const view = orders.addView("orderView");
});
```

`fetch()` 会执行：

* 远程数据获取
* Schema 适配
* 内部状态初始化

所有远程操作都依赖已完成的 fetch。

## 将 schema 用于远程数据

远程响应可能需要字段映射或类型转换。
示例：

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read: {
            url: "https://demodata.grapecity.com/northwind/api/v1/products"
        }
    },
    schema: {
        columns: {
            id: { dataName: "ProductId" },
            name: { dataName: "ProductName" },
            price: { dataName: "UnitPrice", dataType: "number" },
            stock: { dataName: "UnitsInStock", dataType: "number" }
        }
    }
});
```

Schema 配置请参阅 **[Schema](gcdocsite__documentlink?toc-item-id=fe5a35c4-1f4e-4c43-b46a-d456ae391767)** 章节。

## 启用同步（预览）

如需启用数据回写，必须定义额外的远程操作。
示例（单次同步模式）：

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read:   { url: "https://example.com/api/products", method: "GET" },
        create: { url: "https://example.com/api/product", method: "POST" },
        update: { url: "https://example.com/api/product", method: "PUT" },
        delete: { url: "https://example.com/api/product", method: "DELETE" }
    },
    autoSync: true
});
```

同步模式说明请参阅：
