# remote-read-and-adapter

远程表通过 `read` 配置获取数据。
`read` 选项定义：

* 从哪里请求数据
* 如何发送请求
* 如何解释响应结构

默认情况下，响应会被视为标准 JSON 数组。
如果响应遵循某种结构化协议，可以指定适配器。

## 基本 HTTP 读取（默认行为）

如果未指定适配器，响应会被视为记录数组。
示例：

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read: {
            url: "https://example.com/api/products",
            method: "GET"
        }
    }
});

products.fetch();
```

预期响应格式：

```json
[
  { "ProductId": 1, "ProductName": "ItemA", "UnitPrice": 15 },
  { "ProductId": 2, "ProductName": "ItemB", "UnitPrice": 17 }
]
```

如果响应本身就是数组，则不需要适配器。

## REST Adapter

某些 REST API 会返回包装后的结构。
示例响应：

```json
{
  "status": "success",
  "data": [
    { "id": 1, "name": "Item A" },
    { "id": 2, "name": "Item B" }
  ]
}
```

使用 `rest` 适配器提取 `data` 字段：

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read: {
            url: "https://example.com/api/products",
            adapter: "rest"
        }
    }
});
```

使用 REST 适配器时：

* `data` 属性会被视为记录集合。
* 其他包装属性会被忽略。

## OData Adapter

OData 响应会将记录存储在 `value` 属性中。
示例响应：

```json
{
  "@odata.context": "...",
  "value": [
    { "ProductId": 1, "ProductName": "ItemA" }
  ]
}
```

使用：

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read: {
            url: "https://example.com/api/products",
            adapter: "odata"
        }
    }
});
```

适配器会自动提取 `value` 数组。

## OData v4 Adapter

OData v4 遵循相同的 `value` 结构，但可能包含额外元数据。

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read: {
            url: "https://example.com/api/products",
            adapter: "odata4"
        }
    }
});
```

`odata4` 适配器会自动处理 v4 特定的元数据。

## GraphQL Adapter

GraphQL 响应会将记录包装在嵌套的 `data` 对象中。
示例响应：

```json
{
  "data": {
    "users": {
      "data": [
        { "id": "1", "name": "Leanne Graham" }
      ]
    }
  }
}
```

配置示例：

```javascript
const users = dataManager.addTable("users", {
    remote: {
        read: {
            url: "https://graphqlzero.almansi.me/api",
            adapter: "graphql",
            method: "POST",
            body: {
                query: `
                    query {
                        users {
                            data {
                                id
                                name
                                email
                            }
                        }
                    }
                `
            }
        }
    },
    schema: {
        dataPath: "users.data"
    }
});
```

注意：

* GraphQL 通常需要使用 `POST`。
* 必须提供查询。
* `schema.dataPath` 指定记录数组所在的位置。

Schema 详细信息请参阅 **Schema** 章节。

## 使用请求选项

`options` 属性对应标准 `fetch` 配置。
示例：

```javascript
read: {
    url: "https://example.com/api/products",
    method: "POST",
    options: {
        headers: {
            "Content-Type": "application/json"
        }
    }
}
```

这允许：

* 自定义请求头
* 凭据
* 模式配置
* 其他 fetch 设置

## 使用 body

`body` 属性是指定请求体的简化方式。
示例：

```javascript
read: {
    url: "https://graphqlzero.almansi.me/api",
    adapter: "graphql",
    method: "POST",
    body: {
        query: "{ users { data { id name } } }"
    }
}
```

如果同时提供 `body` 和 `options.body`：

* `body` 优先。
* 操作特定的 body 可能会覆盖它。

## 自定义读取处理函数

除了提供 URL 配置，也可以定义函数：

```javascript
const products = dataManager.addTable("products", {
    remote: {
        read: function () {
            return Promise.resolve([
                { ProductId: 1, ProductName: "Chai" }
            ]);
        }
    }
});
```

这允许：

* 完全控制数据获取
* 集成自定义传输层
* 模拟实现

>type=note
> **注意：**
> 基于函数的处理函数无法在导出期间序列化。
