# remote-column-crud

除了行数据同步之外，远程表还可以与服务器同步列定义。
这可以启用：

* 动态创建列
* 更新列属性
* 移除列
* 集中式 schema 管理

列操作需要对应的远程端点。

## 启用远程列管理

如需远程管理列，请配置：

* `getColumns`
* `addColumn`
* `updateColumn`
* `removeColumn`

示例：

```javascript
const orders = dataManager.addTable("orders", {
    remote: {
        read: {
            url: "http://localhost:3000/api/orders",
            method: "GET"
        },
        getColumns: {
            url: "http://localhost:3000/api/orders/columns",
            method: "GET"
        },
        addColumn: {
            url: "http://localhost:3000/api/orders/columns",
            method: "POST"
        },
        updateColumn: {
            url: "http://localhost:3000/api/orders/columns",
            method: "PUT"
        },
        removeColumn: {
            url: "http://localhost:3000/api/orders/columns",
            method: "DELETE"
        }
    },
    autoSync: true
});

orders.fetch();
```

## getColumns

`getColumns` 会从服务器获取列定义。
典型用途：

* 从远程存储初始化 schema
* 确保客户端和服务器端列结构一致

响应应返回与 DataManager 兼容的列定义列表。
列结构细节请参阅 API 参考。

## addColumn

在 TableSheet 中定义新列时，会发送远程请求。
在单次同步模式下：

* 请求会立即发送。
* 服务器会持久化新的列定义。

在批量模式下：

* 变更会先存储在本地。
* 列变更会在 `submitChanges()` 期间发送。

## updateColumn

当列属性被修改时：

* 标题
* 数据类型
* 默认值
* 主键标记

会调用对应的远程端点。
在单次同步模式下：

* 立即发送。

在批量模式下：

* 与其他变更一起存储并提交。

## removeColumn

移除列时：

* 服务器必须删除对应的列定义。
* 相关数据行为取决于服务器实现。

在单次同步模式下：

* 立即发送请求。

在批量模式下：

* 包含在批量载荷中。

## 列变更的批量行为

如果启用了 `batch: true`：

* 行变更和列变更会合并。
* `submitChanges()` 会一起发送所有修改。
* 如果可能，服务器应将该批量请求视为原子操作。

提交流程示例：

```javascript
orders.submitChanges();
```

如需取消挂起的变更：

```javascript
orders.cancelChanges();
```

批量载荷可以包含：

* addColumn
* updateColumn
* removeColumn
* insert
* update
* delete

确切的请求结构由 API 参考定义。

## 自定义列处理函数

除了 URL 配置，也可以将操作定义为函数：

```javascript
const orders = dataManager.addTable("orders", {
    remote: {
        read: function () {
            return Promise.resolve([...]);
        },
        addColumn: function (change) {
            return Promise.resolve(change);
        }
    },
    autoSync: true
});
```

这允许：

* 自定义传输逻辑
* 中间件集成
* 模拟实现

>type=note
> 注意：
> 基于函数的处理函数无法在导出期间序列化。

## 重要约束

远程列同步要求：

* 一致的列标识符（`value`）
* 服务器端支持列持久化
* 正确处理数据类型变更

如果服务器验证失败：

* 操作应返回错误
* 表状态会反映该失败

服务器端 schema 强制规则取决于具体应用。
