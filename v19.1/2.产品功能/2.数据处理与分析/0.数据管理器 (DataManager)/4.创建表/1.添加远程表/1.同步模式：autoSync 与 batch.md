# sync-mode-autosync-vs-batch

远程表支持两种同步模式：

* **单次同步模式**
* **批量同步模式**

同步模式决定：

* 何时将变更发送到服务器
* 请求如何组织
* 变更是否具有事务性

同步模式会在创建表时配置。

## 单次同步模式（autoSync）

在单次同步模式下，每次数据变更都会立即触发远程请求。
通过以下设置启用：

```javascript
autoSync: true
```

示例：

```javascript
const dataManager = spread.dataManager();

const orders = dataManager.addTable("orders", {
    remote: {
        read:   { url: "http://localhost:3000/api/orders", method: "GET" },
        create: { url: "http://localhost:3000/api/orders", method: "POST" },
        update: { url: "http://localhost:3000/api/orders", method: "PUT" },
        delete: { url: "http://localhost:3000/api/orders", method: "DELETE" }
    },
    autoSync: true
});

orders.fetch();
```

行为：

* 插入 → 发送 `create`
* 更新 → 发送 `update`
* 删除 → 发送 `delete`
* 每个操作都会发送单独请求
* 不需要手动提交

在以下情况下使用单次同步模式：

* 需要立即持久化
* 每个操作相互独立
* 相比批处理，更偏好简单性

## 批量同步模式

在批量模式下，变更会存储在本地，直到显式提交。
通过以下设置启用：

```javascript
batch: true
```

示例：

```javascript
const orders = dataManager.addTable("orders", {
    remote: {
        read:  { url: "http://localhost:3000/api/orders", method: "GET" },
        batch: { url: "http://localhost:3000/api/orders/batch", method: "POST" }
    },
    batch: true
});

orders.fetch();
```

行为：

* 插入、更新、删除操作会缓存在本地
* 不会立即发送网络请求
* 所有变更会一起提交

如需发送变更：

```javascript
orders.submitChanges();
```

如需放弃变更：

```javascript
orders.cancelChanges();
```

## 行为对比

| 特性 | 单次同步 | 批量同步 |
| ------- | ----------- | ---------- |
| 网络调用 | 每个操作一次 | 一个请求 |
| 手动提交 | 不需要 | 需要 |
| 类事务行为 | 否 | 是 |
| 失败处理 | 按操作处理 | 整个批次处理 |

批量模式适用于：

* 多个变更必须同时成功或失败
* 需要尽量减少网络流量
* 服务器端实现了事务处理

## 变更生命周期

在单次同步模式下：

1. 用户修改数据
2. 立即发送远程请求
3. 服务器响应更新表状态

在批量模式下：

1. 用户修改数据
2. 变更存储在本地
3. `submitChanges()` 发送所有变更
4. 服务器返回聚合结果
5. 表状态最终确定

## 重要说明

* 必须始终定义 `read`。
* 单次同步模式需要 `create`、`update` 和 `delete`。
* 批量模式需要 `batch`。
* 只应启用一种模式。
* 所有表在编辑前都必须调用 `fetch()`。
