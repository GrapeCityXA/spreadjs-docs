# fetch-reload

[`fetch`](gcdocsite__documentlink?toc-item-id=f2382678-7491-4d87-8523-09bfc84e5b68#fetch) 方法会根据表配置的数据源初始化或刷新表数据。

```typescript
fetch(reload?: boolean): Promise<any>;
```

* 如果表尚未加载，`fetch()` 会初始化表。
* `fetch(true)` 会强制表从配置的数据源重新加载数据。

本节介绍重新加载模式的行为和用法。

## 何时使用 fetch

无论表配置的是：

* 本地数据（`data`），或
* 远程数据（`remote`）

在执行以下进一步操作前，都应始终调用 `table.fetch()`：

* 创建视图
* 绑定到 TableSheet
* 访问表数据
* 创建关系

调用 `fetch()` 可以确保表已完全初始化，并可用于后续操作。

## 基本用法

```javascript
table.fetch().then(function(data) {
  // 此处可以访问数据
});
```

例如：

```javascript
const table = dataManager.addTable("products", {
  data: [
    { id: 1, name: "Pen" },
    { id: 2, name: "Notebook" }
  ]
});

const tableSheet = spread.addSheetTab( 0, "ProductTableSheet", GC.Spread.Sheets.SheetType.tableSheet );

// 使用表之前始终调用 fetch
table.fetch().then(function () {

  const view = table.addView("productView");

  view.fetch().then(function () {
     tableSheet.setDataView(view);
  });

});
```

## 重新加载数据

### 何时使用重新加载

重新加载通常用于远程表，因为底层数据可能会在当前应用会话之外发生变化。
常见场景包括：

* 手动“刷新”按钮。
* 与后端服务定期同步。
* 其他用户更新了数据。
* 重新查询同一端点以获取最新结果。

如需从配置的数据源刷新表数据，请调用：

```javascript
table.fetch(true);
```

>type=note
> **注意：**
>
> * 确保表重新执行其配置的数据源。
> * 实际数据是否变化取决于数据源本身。
> * 重新加载期间的内部更新行为取决于数据源和使用场景。

### 功能影响

调用 `fetch(true)` 时：

* 表数据会重新加载。
* 现有视图会重新计算。
* 排序和筛选规则保持不变。
* 如果数据发生变化，已绑定组件会自动更新。

重新加载不会：

* 重新创建表
* 重新创建视图
* 要求调用 `view.fetch()`
* 要求再次调用 `setDataView()`

如果重新加载的数据与之前结果相同，则不会出现可见变化。

### 排序和筛选行为

如果视图中存在活动的排序或筛选：

* 规则会保留。
* 重新加载后，这些规则会应用到新加载的数据。
* 结果集可能会根据新数据发生变化。

不需要额外操作。

### 示例

```javascript
const dataManager = spread.dataManager();
const tableSheet = spread.addSheetTab( 0, "ProductTableSheet", GC.Spread.Sheets.SheetType.tableSheet );

const products = dataManager.addTable("products", {
  remote: {
    read: {
      url: "https://demodata.grapecity.com/northwind/api/v1/products",
    }
  }
});

// 初始加载
products.fetch().then(() => {

  const view = products.addView("productView");

  view.fetch().then(function () {
     tableSheet.setDataView(view);
  });

  // 稍后：强制重新加载
  document.getElementById("refreshBtn").addEventListener("click", () => {
    products.fetch(true).then(() => {
      tableSheet.setDataView(view);
      console.log("Table data reloaded.");
    });
  });

});
```

`fetch(true)` 之后：

* 表会从远程端点重新请求数据。
* 现有视图规则保持不变。
* TableSheet 会自动反映更新后的数据。

### 切换数据源

除了刷新同一端点外，当表的数据源需要在运行时变更时，也可以使用 `fetch(true)`。
模板化工作流中经常会出现这种场景。
设计人员在开发期间通常会使用测试或演示端点构建电子表格模板。
当模板部署到生产环境时，应用必须将测试端点替换为生产数据源。
在这种情况下：

* 表定义保持不变。
* 远程端点会被更新。
* 使用 `fetch(true)` 从新数据源加载数据。

### 示例

```javascript
var options = myTable.options;

// 替换远程端点（开发 → 生产）
options.remote.read.url = "https://developer.grapecity.com.cn/spreadjs/demos/server/api/Order";

myTable.options = options;

// 从新端点重新加载
myTable.fetch(true).then(function () {

  // 为新数据集重新创建视图
  var view = myTable.addView("myView2");

  view.fetch().then(function () {
     sheet.setDataView(view);
  });

});
```

切换到不同端点时：

* 返回的数据集可能在结构或内容上有所不同。
* 现有视图状态可能无法与新数据对齐。
* 重新创建视图可以确保正确绑定和重新计算。

此模式常用于将模板从开发环境提升到生产环境。
