# view

## 什么是视图

视图（View）定义表数据的结构化方式和展示方式。
在 DataManager 架构中：

* 表负责管理和存储数据。
* 视图定义数据如何对外呈现。
* 工作表（TableSheet / GanttSheet）负责渲染视图。

视图是数据与 UI 之间的结构层。
它决定：

* 哪些字段可见
* 列如何排序和命名
* 值如何格式化
* 是否包含关联表字段
* 应用哪些视觉规则或验证规则

视图不会独立存储数据，而是反映其宿主表的当前状态。

## 为什么使用视图

一个表通常需要服务多个展示场景。
例如：

* 摘要工作表可能只显示关键字段。
* 详细信息工作表可能包含关联表信息。
* GanttSheet 可能需要任务相关的列。
* 分析工作表可能应用条件格式规则。

无需为每个场景修改表 schema，可以创建多个视图。
每个视图都表示同一份表数据的不同投影。

## 数据流中的视图

典型流程如下：

```auto
数据源 → 表 → 视图 → 组件
```

* **Table** 加载并管理原始数据。
* **View** 定义结构和展示方式。
* **Component** 绑定到视图并进行渲染。

这种分离可以确保：

* 数据完整性保留在表层。
* 展示逻辑保留在视图层。
* UI 组件独立于原始数据结构。

## 核心能力

视图提供以下能力：

### 结构控制

* 选择列
* 定义列顺序
* 重命名列
* 添加计算列

### 展示控制

* 配置列宽（像素或星号尺寸）
* 自定义表头样式和布局
* 使用公式或模板格式化单元格内容
* 控制 null 和空值的显示行为

### 基于规则的行为

* 应用条件格式
* 添加迷你图规则
* 定义验证规则
* 添加视图级样式规则

### 跨表投影

* 包含关联表中的字段
* 使用点表示法访问关联数据
* 使用关联字段格式化值

### 运行时管理

* 动态添加或移除列
* 添加或移除样式规则
* 控制自动筛选和排序行为
* 查看总数据长度和可见数据长度

## 与表的关系

* 视图始终属于一个宿主表。
* 一个表可以包含多个视图。
* 移除视图不会影响表数据。
* 修改视图不会改变表 schema。

跨表访问需要先定义关系。

## 必要初始化

创建视图后，调用：

```javascript
view.fetch();
```

这会初始化视图，并使其可用于绑定。
如需强制从数据源重新加载：

```javascript
view.fetch(true);
```

## 绑定目标

视图可以绑定到：

* **TableSheet**
* **GanttSheet**

工作表会渲染视图定义的结构。
