# sparkline-rule

# 迷你图规则

借助迷你图规则，你可通过条件格式将单元格数值渲染为迷你图。

无需在单个单元格中逐一插入迷你图公式，直接对单元格区域应用迷你图规则即可。该规则会自动为区域内每一个单元格生成并渲染对应的迷你图。

该功能内置上下文标识符，能够自动将迷你图配置与规则应用区域、当前单元格进行匹配，彻底摒弃硬编码引用的使用方式。

## 迷你图规则适用场景

满足以下场景时，可使用迷你图规则：

* 需要为整列、整行或指定单元格区域批量添加迷你图
* 需在高度关联的数据区域添加迷你图，例如工作表表格、集算表、数据管理器以及报表模板
* 不想改动原始单元格数据，拒绝使用公式嵌入式迷你图
* 需要通过条件格式优先级统一管理可视化展示规则

## 迷你图规则与公式型迷你图的区别

传统迷你图需要在每个单元格内编写迷你图函数来完成插入操作。
这类公式必须手动明确指定数据范围，必要时还需设置点位索引。
而迷你图规则的使用方式截然不同：

* 仅需对一个区域应用单条规则
* 该区域内所有单元格都会自动渲染成迷你图
* 规则可自动识别解析以下内容：
    * 完整的规则应用区域
    * 当前单元格数值
    * 当前单元格在规则区域内的所在位置

以上运行逻辑依靠两类内置上下文标识符实现。

## 内置上下文标识符

迷你图条件格式规则支持两种标识符：

| 标识符 | 作用层级 | 用途说明 |
| --- | ---- | ---- |
| `$CF_RANGE$` | 规则层级 | 指代条件格式所应用的完整区域 |
| `@` | 单元格层级 | 指代当前单元格数值，或是其在规则区域内的索引位置 |

标识符的使用形式：

1. 直接作为完整参数值使用，示例：`数值: '@'`、`数据点位: '$CF_RANGE$'`
2. 嵌入表达式中使用，示例：`IF(@>0,@,0)`、`SUM($CF_RANGE$)`

`[@销售额]`、`表格1[@[列1]:[列2]]`这类结构化引用会保留原有含义，不会被当作占位符处理。

### $CF\_RANGE$ — 规则层级上下文

`$CF_RANGE$`代表**当前应用迷你图规则的单元格区域**，始终对应条件格式的实际生效范围。

* 若规则应用范围为`B1:B5`，则`$CF_RANGE$`对应`B1:B5`
* 若将规则调整范围至`B1:B10`，`$CF_RANGE$`会自动同步变为`B1:B10`

以往需要硬编码指定数据区域的写法：

```javascript
dataRange: "A1:A5"
```

如今可直接简写为：

```javascript
dataRange: "$CF_RANGE$"
```

**代码示例**

```javascript
sheet.conditionalFormats.addSparklineRule(    
"HISTOGRAMSPARKLINE",    
{        
dataRange: "$CF_RANGE$"    
},    
[new GC.Spread.Sheets.Range(0, 0, 5, 1)]
);
```

**使用优势**

* 可跟随规则应用区域的改动自动适配
* 摆脱固定硬编码区域引用
* 支持`SUM($CF_RANGE$)`等各类表达式运算
* 提升规则通用性与复用性

### @ — 单元格层级上下文

`@`代表规则应用区域内的**当前单元格**，具体含义根据所处参数类型变化：

* 用于`索引`参数：代表当前单元格在`$CF_RANGE$`中从0开始排序的索引值
* 用于`点位索引`参数：代表当前单元格在`$CF_RANGE$`中从1开始排序的索引值
* 用于其他参数：代表当前单元格的实际数值

若`@`出现在`[@销售额]`这类结构化引用内，将维持结构化引用本身含义不变。
如果表达式中使用`@`且当前单元格为空值，`@`会自动转为空字符串，保障表达式正常运行。
部分迷你图类型使用从0起始的`索引`参数，其余类型则使用从1起始的`点位索引`参数，具体参数定义可查阅对应接口文档。

## 示例1：借助@调用数值与索引

以下示例用于搭建履约数据看板：

* 在「准时完成核心指标」列中，`@`代表当前单元格的实际数值
* 在「与目标值差值」列中，`@`代表当前行在规则区域内从0开始排序的索引值

```javascript
var sheet = spread.getActiveSheet();
// Title
sheet.addSpan(0, 0, 1, 6);
sheet.setValue(0, 0, "Weekly Fulfillment Dashboard");
// Header
sheet.setArray(1, 0, [[
    "Warehouse",
    "Target Units",
    "Shipped Units",
    "On-Time Rate",
    "On-Time KPI",
    "Variance vs Target"
]]);
// Data
var data = [
    ["North Hub", 1200, 1260],  // +5%
    ["East Hub", 950, 910],  // -4%
    ["South Hub", 1100, 1060],  // -3.6%
    ["West Hub", 780, 820],  // +5%
    ["Central Hub", 1350, 1290]   // -4.4%
];
sheet.setArray(2, 0, data);
sheet.getRange('D3:D7').formula("=C3/B3",true);
sheet.getRange('E3:E7').formula("=C3/B3",true);
sheet.getRange(2, 1, data.length, 2).formatter("#,##0");
sheet.getRange(2, 3, data.length, 2).formatter("0.0%");
// Optional column width for better visuals
sheet.getRange("A:D").width(120);
sheet.getRange("E:F").width(220);
sheet.getRange("3:7").height(42);
// Sparkline Rule
var cfs = sheet.conditionalFormats;
// @ = current cell value in E3:E7.
var gaugeRule = cfs.addSparklineRule(
    "GAUGEKPISPARKLINE",
    {
        targetValue: 1, // targetValue = 1 represents a 100% on-time fulfillment goal.
        currentValue: "@",
        minValue: 0,
        maxValue: 1.2,
        showLabel: false,
        gaugeType: 2,
        colorRange: [
            { start: 0, end: 0.9, color: "#D9534F" },
            { start: 0.9, end: 1, color: "#F0AD4E" },
            { start: 1, end: 1.2, color: "#5CB85C" }
        ]
    },
    [new GC.Spread.Sheets.Range(2, 4, data.length, 1)]
);
// @ = current row index inside F3:F7.
var varianceRule = cfs.addSparklineRule(
    "LOLLIPOPVARISPARKLINE",
    {
        plannedValue: "$B$3:$B$7",
        actualValue: "$C$3:$C$7",
        index: "@",
        reference: 0,
        mini: -0.15,
        maxi: 0.15,
        tickUnit: 0.05,
        legend: true,
        colorPositive: "#5CB85C",
        colorNegative: "#D9534F",
        lollipopHeaderColor: "#3F4E63"
    },
    [new GC.Spread.Sheets.Range(2, 5, data.length, 1)]
);
```

**运行效果说明**

* 在当前数值参数中，`@`会自动读取E3至E7每个单元格对应的履约指标数值
* 在索引参数中，`@`会依次为F3至F7单元格匹配0、1、2、3、4的排序索引
* 仪表盘样式迷你图可直观展示各仓库是否达成100%准时履约目标
* 棒棒糖样式迷你图无需固定行索引，即可逐行对比实际发货量与目标发货量的差异

> 备注：
> 示例中为方便理解，直接写明了目标数值区域B3:B7与实际数值区域C3:C7。
> 实际正式项目开发中，可搭配`$CF_RANGE$`编写表达式，规避固定单元格地址写法，具体用法参考示例2。

## 示例2：使用$CF\_RANGE$取消硬编码数据区域

该示例以规则应用整体区域为上下文，为差异列所有单元格生成差值对比棒棒糖迷你图。

```javascript
var sheet = spread.getActiveSheet();
// 合并单元格设置标题
sheet.addSpan(0, 0, 1, 4);
sheet.setValue(0, 0, "预算差异分析表");
// 设置表头
var headers = ["部门名称", "预算金额(千元)", "实际支出(千元)", "收支差异"];
sheet.setArray(1, 0, [headers]);
// 录入业务数据
var data = [    
["研发部", 850, 760],    
["市场部", 420, 500],    
["销售部", 380, 330],    
["运维部", 260, 305],    
["基建部", 520, 475]
];
sheet.setArray(2, 0, data);
// 自定义列宽优化展示效果
sheet.getRange("A:D").width(150);
// 高级用法：添加迷你图规则
sheet.conditionalFormats.addSparklineRule(    
"LOLLIPOPVARISPARKLINE",    
{        
// $CF_RANGE$ 对应D3:D7单元格区域        
plannedValue: "OFFSET($CF_RANGE$,0,-2)",// 向左偏移两列，对应预算金额B列        
actualValue: "OFFSET($CF_RANGE$,0,-1)",// 向左偏移一列，对应实际支出C列        
index: "@",        
reference: 0,        
legend: true,        
colorPositive: "#4CAF50",        
colorNegative: "#E53935"    
},    
[new GC.Spread.Sheets.Range(2, 3, data.length, 1)]// 规则应用至收支差异列D3:D7
);
```

**该用法实用价值**

* 规则始终依据当前生效的条件格式区域进行数据运算
* 新增或删除数据行时，无需手动修改预算、实际支出的数据引用范围
* 规则具备自适应能力，可直接复用至其他同类表格

## 报表模板使用场景

在报表模板内使用迷你图规则时，规则预先定义在模板单元格中，运行程序后模板单元格会自动批量扩展生成数据行。

若迷你图相关配置需要引用模板单元格扩展后生成的实际单元格区域，可使用`R.V(...)`函数公式。
`R.V(引用位置)`能够匹配获取指定模板单元格在运行后扩展生成的实际数据区域。

**使用示例**
![image](/DOCUMENT_SITE_LINK_PREFIX_HERE/document-site-files/images/0f73f140-2ccc-4566-a244-10944255eeb4/image-20260420.da48ea-20260525.0a993f.png?width=600)

```auto
const spread = new GC.Spread.Sheets.Workbook("ss");
const dataManager = spread.dataManager();
// 1. 配置数据源
const budgetData = [    
{ department: "研发部", planned: 850, actual: 760 },    
{ department: "市场部", planned: 420, actual: 500 },    
{ department: "销售部", planned: 380, actual: 330 },    
{ department: "运维部", planned: 260, actual: 305 },    
{ department: "基建部", planned: 520, actual: 475 }
];
dataManager.addTable("Budget", {    
data: budgetData
});
//2. 创建报表
const reportSheet = spread.addSheetTab(    
0,    
"预算报表",    
GC.Spread.Sheets.SheetType.reportSheet
);
const templateSheet = reportSheet.getTemplate();
const columns = ['department', 'planned', 'actual'];
columns.forEach((columnName, i) => {    
templateSheet.setValue(0, i, `${columnName}`);    
templateSheet.setTemplateCell(1, i, {        
type: 'List',        
binding: `Budget[${columnName}]`,    
});    
templateSheet.setColumnWidth(i, 80)
});
templateSheet.setValue(0, 3, "收支差异");
templateSheet.setTemplateCell(1, 3, {    
type: "List"
});
templateSheet.setColumnWidth(3, 150);
//3. 配置迷你图规则
templateSheet.conditionalFormats.addSparklineRule(    
"LOLLIPOPVARISPARKLINE",    
{        
plannedValue: "R.V(B2)",        
actualValue: "R.V(C2)",        
index: "@",        
reference: 0,        
legend: true,        
colorPositive: "#2E7D32",        
colorNegative: "#C62828"    
},    
[new GC.Spread.Sheets.Range(1, 3, 1, 1)]
);
// 4. 刷新报表加载数据
reportSheet.refresh();
```

**代码解析**

* 迷你图规则设置在模板单元格D2上
* 刷新报表后，模板行会根据绑定的数据源自动批量扩展
* `R.V(D2)`可精准匹配模板单元格D2运行后扩展出的实际数据区域
* `index: '@'`代表当前单元格在规则应用区域内从0开始排序的位置

在报表模板中，凡是需要引用模板绑定单元格扩展后实际区域的迷你图配置，均可使用`R.V(...)`函数实现。

## 运行规则与相关规范

1. 支持使用的工作表类型：普通工作表、集算表、报表
2. 迷你图规则中，「条件成立则停止判定」属性固定默认为关闭状态
3. 相对引用的基准位置统一锁定在条件格式应用区域的起始位置
4. 类公式格式的配置参数，在执行复制、移动、区域调换、工作表重命名操作时，会自动完成引用地址适配调整
5. 迷你图规则可参与条件格式优先级排序管理

## 导出为Excel文件相关说明

* 开启「按视图样式保存」功能：迷你图会以图片形式导出，推荐使用该模式
* 未开启该功能：迷你图会降级转为通用数据条格式
* 迷你图专属视觉样式无法完整保留
* 仅保留原有条件格式的优先级设置

## 可视化设计器适配说明

在设计器中将格式样式选定为迷你图后：

* 属性面板会根据所选迷你图类型自动切换展示对应配置项
* 多项配置参数默认自带「自动匹配」选项：
    * 实际数值参数默认自动匹配`$CF_RANGE$`
    * 点位索引参数默认自动匹配`@`

取消勾选「自动匹配」选项后，即可手动自定义各项配置参数。
