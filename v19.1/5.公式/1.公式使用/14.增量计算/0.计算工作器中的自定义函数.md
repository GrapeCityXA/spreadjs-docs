# custom-functions-in-calc-worker

当加载calcWorker插件且开启`incrementalCalculation`配置项后，SpreadJS会在Web Worker子线程中计算公式，而非主线程。
在此运行模式下，内置公式直接在Calc Worker中执行；但自定义函数仍在主线程运算：当运算子线程读取到自定义函数时，会将运算任务转交UI主线程执行，运算结果再回传给运算子线程。

从19.1.0版本开始，SpreadJS支持符合条件的自定义函数直接在Calc Worker内部运行。该特性省去了运算子线程与UI主线程之间的跨线程消息传输，在高频调用自定义函数时能够减少通讯开销。

## 启用条件

自定义函数想要在Calc Worker中运行，需同时满足以下三点：

1. 已加载calcWorker插件。
2. `spread.options.incrementalCalculation = true`配置生效。
3. 自定义函数的`supportCalcWorker()`方法返回`true`。

>type=note
> **注意事项：**
>
> * 若`incrementalCalculation`配置处于关闭状态，`supportCalcWorker()`配置不会生效。
> * 未加载calcWorker插件时，所有计算逻辑始终在主线程执行。

## 运行机制

当`supportCalcWorker()`返回`true`时，自定义函数的实现代码会被序列化并载入Calc Worker，后续全部运算逻辑都在子线程中完成。

### 相关限制

* 所有业务逻辑代码必须编写在`evaluate()`或`evaluateAsync()`方法内部。
* 函数原型属性与实例成员无法保留。
* 无法调用`Workbook`、`Worksheet`以及`GC.Spread.Sheets`相关接口。
* 仅可使用运算上下文、入参以及Web Worker原生内置接口。

工具辅助方法需要定义在函数方法体内。

### 支持的返回值类型

可在Calc Worker运行的自定义函数，支持返回下述类型数据：

* 基础原始类型（`字符串`、`数字`、`布尔值`、`空值`）
* `GC.Spread.CalcEngine.CalcArray`数组对象
* 计算引擎错误对象（例如：`GC.Spread.CalcEngine.Errors.Value`）

当函数返回`CalcArray`对象或计算引擎错误对象时，返回效果和在主线程执行运算保持一致。

## 开启子线程运算

适用基类：

* `GC.Spread.CalcEngine.Functions.Function`
* `GC.Spread.CalcEngine.Functions.AsyncFunction`

```javascript
supportCalcWorker() {    
return true;
}
```

## 元数据传输规则

自定义函数在Calc Worker中运行时：

* 运算逻辑在子线程执行。
* 受支持的函数元数据会自动完成跨线程传输。
* 原型扩展与不兼容主线程的特性无法使用。

开启子线程运行后，不要依赖基于原型的业务逻辑或主线程独有的运行特性。

## 代码示例

**基础示例：在Calc Worker运行的工具类函数**

```javascript
function Base64Decode() {}
Base64Decode.prototype = new GC.Spread.CalcEngine.Functions.Function('BASE64DECODE', 1, 1);
Base64Decode.prototype.supportCalcWorker = function () {
    return true;
};
Base64Decode.prototype.evaluate = function (value) {
    if (typeof value !== 'string') {
        return '#VALUE!';
    }
    try {
        return atob(value);
    } catch {
        return '#VALUE!';
    }
};
sheet.addCustomFunction(new Base64Decode());
spread.options.incrementalCalculation = true;
```

**进阶示例：首次运算初始化函数与全局缓存**

```javascript
class Hash extends GC.Spread.CalcEngine.Functions.AsyncFunction {
    constructor() {
        super('HASH', 1, 1);
    }
    supportCalcWorker() {
        return true;
    }
    evaluateAsync(context, input) {
        const global = globalThis;
        if (!global.cache) {
            global.cache = {};
        }
        if (global.cache[input]) {
            return global.cache[input];
        }
        const encoder = new TextEncoder();
        const data = encoder.encode(String(input));
        crypto.subtle
            .digest('SHA-256', data)
            .then((buffer) => {
                const hex = Array.from(new Uint8Array(buffer))
                    .map((b) => b.toString(16).padStart(2, '0'))
                    .join('');
                global.cache[input] = hex;
                context.setAsyncResult(hex);
            })
            .catch(() => {
                context.setAsyncResult('#HASH_ERROR!');
            });
    }
}
GC.Spread.CalcEngine.Functions.defineGlobalCustomFunction('HASH', new Hash());
```

## 开发规范

编写适配Worker运行的自定义函数需遵循以下准则：

* 函数实现代码做到功能自包含。
* 辅助工具逻辑写在求值方法内部。
* 仅使用Web Worker环境兼容的接口。
* 杜绝依赖UI主线程相关能力。
* 保证所有参数与返回数据支持序列化。

在公式数量庞大、单元格密集的工作簿中，主线程调度容易成为性能瓶颈，此时启用子线程运算的收益最高。

## 性能说明

开启自定义函数的Worker运行能力后，将消除Calc Worker和UI主线程之间的跨线程通讯开销。

未配置`supportCalcWorker()`时：

* 运算子线程碰到自定义函数会暂停计算。
* 运算任务转交主线程执行。
* 运算结果回传给子线程。

每次调用都会产生跨线程消息传输损耗。

启用`supportCalcWorker()`后：

* 函数全程在子线程内部运行。
* 不存在跨线程数据交互。

在以下场景性能提升效果尤为明显：

* 大批量单元格重复调用同一个自定义函数。
* 函数代码精简但调用频次极高。
* 多层公式依赖链触发反复求值。

实际性能提升幅度取决于函数调用次数与自身逻辑复杂度。
