# custom-functions-in-calc-worker

加载calcWorker插件并开启`incrementalCalculation`增量计算功能后，SpreadJS会在网页工作线程中运算公式，而非主线程。
在此模式下，内置公式可直接在计算工作线程内执行；但自定义函数依旧在主线程运行：当工作线程读取到自定义函数时，会将执行任务转交至界面线程，运算完成后再把结果传回工作线程。
从19.1.0版本开始，SpreadJS支持符合条件的自定义函数直接在计算工作线程内运行。该特性可消除工作线程与界面线程之间的跨线程消息传递，大幅降低自定义函数频繁调用时产生的通信开销。

## 使用要求

自定义函数仅满足以下全部条件，才可在计算工作线程中运行：

1. 已加载calcWorker插件
2. 配置`spread.options.incrementalCalculation = true`开启增量计算
3. 自定义函数的`supportCalcWorker()`方法返回值为`true`

>type=info
> **注意事项：**
>
> * 若关闭`incrementalCalculation`增量计算，`supportCalcWorker()`方法设置将失效
> * 未加载calcWorker插件时，所有计算操作始终在主线程执行

## 执行机制

当`supportCalcWorker()`方法返回`true`时，自定义函数的实现逻辑会被序列化并载入计算工作线程，全程在工作线程内完成运算。

### 运行限制

* 所有业务逻辑必须编写在`evaluate()`同步求值方法或`evaluateAsync()`异步求值方法内部
* 无法保留原型属性与实例成员属性
* 不可调用工作簿、工作表以及`GC.Spread.Sheets`相关接口
* 仅可使用求值上下文、传入参数以及网页工作线程原生内置接口
* 工具辅助方法必须定义在函数主体内部

## 开启工作线程运行能力

该能力适用于以下两类自定义函数基类：

* `GC.Spread.CalcEngine.Functions.Function` 同步自定义函数
* `GC.Spread.CalcEngine.Functions.AsyncFunction` 异步自定义函数

```javascript
supportCalcWorker() {    
    return true;
}
```

## 元数据传递规则

自定义函数在计算工作线程内运行时：

* 求值逻辑在工作线程中执行
* 兼容的函数元数据会自动完成传输
* 原型扩展功能以及不兼容线程运行的逻辑均无法使用

开启工作线程运行模式后，请勿依赖原型相关逻辑与界面线程专属运行特性。

## 代码示例

**基础示例：可在计算工作线程运行的工具函数**

```javascript
function Base64Decode() {}
Base64Decode.prototype = new GC.Spread.CalcEngine.Functions.Function('BASE64DECODE', 1, 1);
Base64Decode.prototype.supportCalcWorker = function () {
    return true;
};
Base64Decode.prototype.evaluate = function (value) {
    if (typeof value !== 'string') {
        return '#VALUE!';
    }
    try {
        return atob(value);
    } catch {
        return '#VALUE!';
    }
};
sheet.addCustomFunction(new Base64Decode());
spread.options.incrementalCalculation = true;
```

**进阶示例：首次求值初始化函数与全局缓存**

```javascript
class Hash extends GC.Spread.CalcEngine.Functions.AsyncFunction {
    constructor() {
        super('HASH', 1, 1);
    }
    supportCalcWorker() {
        return true;
    }
    evaluateAsync(context, input) {
        const global = globalThis;
        if (!global.cache) {
            global.cache = {};
        }
        if (global.cache[input]) {
            return global.cache[input];
        }
        const encoder = new TextEncoder();
        const data = encoder.encode(String(input));
        crypto.subtle
            .digest('SHA-256', data)
            .then((buffer) => {
                const hex = Array.from(new Uint8Array(buffer))
                    .map((b) => b.toString(16).padStart(2, '0'))
                    .join('');
                global.cache[input] = hex;
                context.setAsyncResult(hex);
            })
            .catch(() => {
                context.setAsyncResult('#HASH_ERROR!');
            });
    }
}
GC.Spread.CalcEngine.Functions.defineGlobalCustomFunction('HASH', new Hash());
```

## 开发设计规范

编写适配工作线程运行的自定义函数需遵循以下规范：

* 保证函数逻辑独立完整，无外部强依赖
* 所有辅助运算逻辑统一写在求值方法内
* 仅使用网页工作线程安全可用的应用程序接口
* 摒弃所有依赖界面线程的业务逻辑
* 确保函数内用到的所有数据都支持序列化传输

在表格数据量大、公式数量密集，且主线程运算出现性能瓶颈的表格文档中，启用工作线程运行自定义函数的优化效果最为显著。

## 性能优化要点

为自定义函数开启工作线程运行模式，能够彻底消除计算工作线程与界面线程之间的跨线程数据通信流程。
未配置`supportCalcWorker()`时：

* 工作线程读取到自定义函数会暂停运算
* 将运算任务移交至主线程处理
* 主线程运算完毕后回传结果至工作线程
    每一次函数调用都会产生消息传递带来的性能损耗。

开启`supportCalcWorker()`配置后：

* 自定义函数全程在工作线程内独立运行
* 不存在任何跨线程数据交互

以下场景中性能提升效果最为突出：

* 大量单元格同时调用同一自定义函数
* 函数逻辑简洁但调用频次极高
* 多层级公式依赖引发反复求值运算

实际性能提升幅度，取决于函数调用总次数以及函数自身逻辑的复杂程度。
