# data-change

## 概述

DataManager 作为 SpreadJS 中的核心组件，主要负责数据源的管理工作。它能够将来自不同数据源的数据引入，并为 SpreadJS 的各类组件提供数据支持。当用户在使用这些组件进行数据的创建（Create）、读取（Read）、更新（Update）和删除（Delete）操作（即 CRUD 操作）时，就需要考虑将数据变更同步回各个数据源，以实现数据的持久化存储。
DataManager 提供了两种数据同步方式：

* 直接同步 - autoSync
* 批量同步 - batch

在使用 [addTable](https://docs.grapecity.com.cn/spreadjs/api/v18/classes/GC.Data.DataManager#addTable) 方法时，可以通过 `dataSourceOption` 参数进行相关配置。

> **注意：**
>
> * 数据同步功能仅适用于远端数据（Remote），通过 local 模式加载的数据不支持数据同步。
> * 由于涉及数据变更操作，本章节将以 TableSheet 为例进行详细讲解。

## 直接同步

当使用 TableSheet 展示数据时，用户可能会直接对数据进行修改。TableSheet 提供了 `saveRow` 方法，用于提交行数据的变更。若希望将这些数据变更直接同步到服务端的数据源，可以将 `autoSync` 设置为 `true`。
`autoSync` 会根据保存的变更类型调用特定的方法，具体如下：

* 若修改了某一行数据，会触发 `update` 方法。
* 若新增了某一行数据，会触发 `create` 方法。

直接同步能够立即将提交的变更更新到数据源，在数据变更频率不高的场景下，这种方式非常适用。示例代码如下：

```javascript
var productTable = dataManager.addTable('productTable', {
    autoSync: true,
    remote: {
        read: function (): Promise<any[]> {
            return fetch(url, options);
        },
        update: function (item): Promise<any> {
            options.body = item;
            return fetch(url, options);
        },
        create: function (item): Promise<any> {
            options.body = item;
            return fetch(url, options);
        },
        delete: function (item): Promise<boolean> {
            return fetch(url + '?id=' + item.id, options);
        },
    },
});
```

## 批量同步

在数据变更频繁的场景下，直接同步会导致向服务端发送大量请求，可能会触发服务降级。此时，可以考虑使用批量同步的方式。以 TableSheet 为例，当用户修改了多行数据后，可通过 `submitChange` 方法提交 TableSheet 中的所有变更。
若开启了 `batch` 模式，就可以通过一次请求将所有数据同步回服务端。示例代码如下：

```javascript
var productTable = dataManager.addTable("productTable", {
    batch: true,
    remote: {
        read: function (): Promise<any[]> {
            return fetch(url, options);
        },
        batch: function (dataChanges: any[]): Promise<any[]> {
            options.body = dataChanges;
            return fetch(url, options);
        }
    }
});
```

## 请求处理

### 直接发送请求

DataManager 支持直接向 RESTful API 发送对应的请求。如果 API 仅用于单纯的数据处理，无需进行认证等操作，可以直接使用 URL 方式配置同步数据的方法。示例代码如下：

```javascript
var productTable = dataManager.addTable('productTable', {
    batch: true,
    remote: {
        read: {
            url: 'http://localhost:9595/api/data/json',
        },
        update: {
            url: 'http://localhost:9595/api/data/json',
            method: 'PUT',
        },
        batch: {
            url: 'http://localhost:9595/api/data/json',
            method: 'POST',
        },
    },
});
```

### 自定义函数

在某些场景下，直接向 API 发送请求可能无法满足业务需求，例如：

* API 接口需要进行认证。
* 发送请求前需要对数据进行处理。

使用自定义函数时，需注意以下几点：

* `read` 函数的返回值是封装所有数据的 `Promise`。
* 自动同步（`autoSync`）所使用的 `create`、`update`、`delete` 方法的返回值是 API 请求后返回数据的 `Promise`。
* 批量同步（`batch`）所使用的 `batch` 方法的返回值是 API 请求返回数据的 `Promise`。

下面的代码示例展示了如何创建和实现自定义请求函数：

```javascript
// 创建自定义请求函数
function sendRequest(url, options) {
    options.method = options.method || 'POST';
    let token = 'your token'; // 如果 API 需要认证，添加 token
    options.headers = { 'Content-Type': 'application/json; charset=utf-8', "Authorization": token };
    if (options.body) {
        options.body = JSON.stringify(options.body);
    }
    return fetch(url, options).then((resp) => {
        if (resp.ok) {
            return resp.json();
        } else {
            throw resp.statusText;
        }
    });
}

// 初始化数据管理器
var dataManager = spread.dataManager();
var myTable = dataManager.addTable('myTable', {
    remote: {
        read: function () {
            return sendRequest(apiUrl, { method: 'GET' });
        },
        update: function (item) {
            return sendRequest(apiUrl, { body: item, method: 'PUT' });
        },
        create: function (item) {
            return sendRequest(apiUrl, { body: item });
        },
        delete: function (item) {
            return sendRequest(apiUrl, { body: item, method: 'DELETE' });
        },
        batch: function (changes) {
            return sendRequest(batchApiUrl, { body: changes });
        },
    },
    batch: true,
    onFailed: function (type, args) {
        console.log('error', type, args);
    },
});
```

## 请求及服务端响应

在数据同步时，针对不同的前端请求，服务端的响应存在一些要求，具体的请求及响应信息请参考如下表格：

| 操作 | 请求类型 | 请求数据 | 返回数据 |
| --- | ---- | ---- | ---- |
| update | POST | 更新的数据 | 更新的数据 |
| read | GET | 无数据 | 数据项数组 |
| delete | DELETE | 删除的数据项或数组 | 没有限制 |
| create | POST | 插入的数据项 | 插入的数据项 |
| batch | POST | 一个对象数组，其中每个对象都包含一个 "类型 "属性。<br>这个操作类型可以是 "更新"、"插入 "或 "删除"。<br>"dataItem"属性是当前记录。<br>'sourceIndex'属性是记录的索引。'<br>可选的'oldDataItem'属性是原始记录。<br>例如:<br>[ {"type":"delete","dataItem":{...}, "sourceIndex":5},<br>{"type":"insert","dataItem":{...}, "sourceIndex":3},<br>{"type":"update","dataItem":{...}, "oldDataItem":{...}, "oldDataItem":{...}, "sourceIndex":1}] | 一个对象数组，每个对象包含一个'success'属性，表示操作的成功或失败，还有一个可选的'data'属性，是当前的记录，只用于'插入'操作。 比如说<br>[{"succeed":true}, {"succeed":false}, {"succeed": true}] |
